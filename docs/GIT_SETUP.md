# Pushing this to your team repository

## Read this first: a copyright decision

`data/extracted/` and `data/lexicon_candidate/` contain **verbatim dictionary
text** — 9,763 entries with full definitions from Samson's *Kapampangan
Dictionary*, plus glossary entries from Mirikitani's *Speaking Kapampangan*
(University of Hawai'i Press, ISBN 9780824885922).

Pushing those to a **public** repository republishes copyrighted material.

| Your repo is | Do this |
|---|---|
| **Private** (recommended for thesis work) | Comment out the four `data/extracted` / `data/lexicon_candidate` lines in `.gitignore`. Repo becomes ~52 MB. |
| **Public** | Leave `.gitignore` as shipped. Repo is **3.7 MB**. Teammates regenerate the data by running stages 20 and 22 from their own PDF copies. |

The source PDFs are excluded either way (`*.pdf`). Never commit those.

## First time — create the repo

In the VS Code terminal, inside `kapampangan-morphbpe`:

```powershell
git init -b main
git add .
git commit -m "Morphologically-aware BPE tokenizer for Kapampangan"
```

Check what you are about to publish **before** connecting to GitHub:

```powershell
git count-objects -vH        # look at "size-pack"
git ls-files | measure       # how many files
```

Then create an empty repo on GitHub (no README, no .gitignore — you already
have both) and:

```powershell
git remote add origin https://github.com/YOUR-TEAM/YOUR-REPO.git
git push -u origin main
```

## If your team repo already exists

Clone it, copy your work in, commit:

```powershell
cd C:\Users\Gabo\Downloads
git clone https://github.com/YOUR-TEAM/YOUR-REPO.git team-repo
robocopy DATASET\kapampangan-morphbpe team-repo /E /XD .git __pycache__ .venv
cd team-repo
git add .
git commit -m "Add tokenizer pipeline, dictionary extraction, candidate lexicon"
git push
```

`robocopy /E` copies subfolders; `/XD` skips the ones you never want.

## Working on a branch (what you said you wanted)

```powershell
git checkout -b tokenizer-morphbpe
git add .
git commit -m "Add Morph-BPE tokenizer pipeline"
git push -u origin tokenizer-morphbpe
```

Then open a Pull Request on GitHub so your groupmates can review before it
reaches `main`.

## Everyday commands

```powershell
git status                       # what changed
git add .                        # stage everything
git commit -m "what you did"     # save a checkpoint
git push                         # send to GitHub
git pull                         # get your teammates' work
```

VS Code has all of this in the **Source Control** panel (`Ctrl+Shift+G`) if you
prefer clicking: stage with `+`, type a message, click **Commit**, then
**Sync Changes**.

## What gets committed, and why

| Committed | Why |
|---|---|
| `src/`, `scripts/`, `tests/` | the code |
| `config/pipeline.yaml` | every setting, so runs are reproducible |
| `data/lexicon/*.tsv` | the Lexicon Dictionary — **your team edits this by hand**, so it must be versioned |
| `data/gold/morpheme_gold.tsv` | human annotation, once it exists — irreplaceable |
| `artifacts/tokenizer/*.json` | the trained tokenizer (~1 MB); lets a reviewer reproduce your tables |
| `docs/`, `notebooks/` | documentation and the Colab notebook |

| Not committed | Why |
|---|---|
| `data/raw/`, `data/processed/` | regenerated by stages 10 and 11 in seconds |
| `data/extracted/`, `data/lexicon_candidate/` | copyrighted dictionary text (public repos only) |
| `*.pdf` | copyrighted sources; large |
| `.venv/`, `__pycache__/` | machine-specific |
| `artifacts/nmt/**/*.pt` | model checkpoints, hundreds of MB |

The `.gitattributes` file forces LF line endings so the same file does not show
up as "changed" just because one teammate edited it on Windows and another in
Colab.

---

## Two things that will bite you

**1. `data/lexicon/` is hand-edited AND machine-generated.**
`scripts/10_ingest_dataset.py` and `24_merge_candidate_lexicon.py` **overwrite**
`roots.tsv`, `variants.tsv` and the affix files. If a teammate spends a day
filling in `WORKLIST_unanalysed.tsv` and someone else re-runs the ingest, that
work is gone.

Protect it: keep validated entries in `function_words.tsv`, `clitics.tsv` and
`orthography_rules.tsv` — the merge never touches those three. Commit before
re-running any stage.

**2. Do not commit `.venv/`.** It is hundreds of MB, machine-specific, and
useless to anyone else. It is already in `.gitignore`; just do not force-add it.
